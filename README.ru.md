# amnezia-ru-split

[English](README.md) | Русский | [简体中文](README.zh-CN.md)

Российские сайты напрямую при включённой AmneziaVPN на Linux, и VPN, который не убивает интернет.

Это не плагин самого клиента, а вспомогательный root-скрипт с NetworkManager-хуком и systemd-таймером.
Клиент и его настройки он не меняет.

## Что решает

1. **Российские сайты напрямую.** Выбранные публичные IPv4-префиксы идут через физический шлюз, остальное через
   VPN. Скрипт добавляет маршруты (`proto 186 metric 42760`) и правила `ACCEPT` для портов 80/443 в цепочку
   kill switch Amnezia `amnvpn.110.allowNets`, иначе kill switch этот трафик режет.
2. **«Подключаюсь, и интернет пропадает».** Демон AmneziaVPN читает таблицу маршрутов в буфер 8 КиБ. Если дамп
   больше (160+ маршрутов из п. 1 его раздувают), демон не находит шлюз, пишет
   `No default gateway available, skipping exclusion route` и не исключает сервер из туннеля. UDP самого VPN уходит
   в `amn0`, handshake не проходит, kill switch блокирует всё. Скрипт держит постоянный маршрут до сервера через
   физический шлюз, и это больше не важно.

Проверьте, затронуты ли вы: `tools/netlink-check.py` (без root) эмулирует чтение и печатает `AFFECTED` или `OK`.

О достоверности: причина установлена эмуляцией чтения netlink и совпадением с логом демона, исходники демона не
читались. Проверено на AmneziaVPN 5.0.3.0 (AmneziaWG), Arch Linux, ядро 7.2.8.

## Требования

Linux, AmneziaVPN, NetworkManager, systemd, iptables, iproute2, python3, curl (для `health`).

## Установка

```sh
sudo install -d /etc/amnezia-ru-split
sudo install -m 644 examples/vpn-endpoints.example /etc/amnezia-ru-split/vpn-endpoints   # впишите IP вашего сервера
cp examples/routes.ru-sites.json routes.json                                             # или свой список префиксов
./amnezia-ru-split plan --routes routes.json     # пробный прогон: покажет план, ничего не меняет, root не нужен
# подключите VPN, затем:
sudo ./amnezia-ru-split install --routes routes.json
```

`install` применяет маршруты, проверяет, что трафик идёт через `amn0`, а внешний IP есть в `vpn-endpoints`, затем
ставит `/usr/local/libexec/amnezia-ru-split`, NM-хук `90-amnezia-ru-split` и таймер на 30 секунд. При любой ошибке
всё откатывается. Установка поверх существующей отклоняется.

Формат `routes.json` совпадает с экспортом «сайтов» раздельного туннелирования Amnezia:
`[{"hostname": "77.88.0.0/18", "ip": ""}]`. Только публичный IPv4, префикс не шире /12.

## Настройка (`/etc/amnezia-ru-split/`)

| Файл | Зачем |
| --- | --- |
| `routes.json` | префиксы, которые идут напрямую |
| `vpn-endpoints` | публичные IPv4 ваших VPN-серверов, по одному в строке; при смене сервера добавьте новый |
| `health-hosts` | необязательно: сайты, которые должны отвечать 200 по HTTPS при включённом VPN (`install`, `health`) |

`health` обращается к `api.ipify.org`, чтобы узнать внешний IP.

## Пример списка маршрутов

В `examples/routes.ru-sites.json` 162 префикса из настройки автора: диапазоны Яндекса, VK, Mail.ru, OK, Ozon,
Avito, Rutube, Госуслуг и некоторых российских операторов, плюс девять маршрутов на отдельные адреса CDN. Это
снимок на 2026-09-30. В тот день разрешённые адреса ya.ru, vk.com, mail.ru, ok.ru, ozon.ru, wildberries.ru,
avito.ru, gosuslugi.ru, kinopoisk.ru, rutube.ru и dzen.ru шли через физический интерфейс, а 2gis.ru нет (он шёл
через VPN). Адреса сайтов меняются, поэтому считайте файл отправной точкой и обновляйте свой список.
`examples/routes.example.json` — короткий образец формата из трёх строк, его использует тест.

## Проверка и откат

```sh
tests/sandbox.sh                                     # 16 проверок в одноразовом namespace, хост не трогает
./amnezia-ru-split health                            # живая проверка при включённом VPN
sudo /usr/local/libexec/amnezia-ru-split uninstall   # убирает только своё, VPN не отключает
```

## Чего в проверках нет

- `install` и `uninstall` (пишут в `/etc`, включают systemd) в песочнице не выполнялись.
- Холодный старт настоящего демона Amnezia (перезагрузка, переподключение Wi-Fi) проверен вручную только на одной
  машине.

## Ограничения

Только IPv4 и только порты 80/443 для прямых сайтов. Имя цепочки `amnvpn.110.allowNets` взято из текущей версии
клиента, другая версия может назвать её иначе. Если чтение шлюза в клиенте починят, скрипт должен продолжить
работать (маршрут до сервера просто окажется лишним), но это не проверялось.
